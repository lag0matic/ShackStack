## Current Application State

ShackStack is in a broadly usable 1.0-ish state. The app has moved toward a desk-based workflow where the main window is mostly a launchpad and operating work happens inside mode desks.

Functional or mostly functional:

- FT8: receive/transmit, time-sync helper, offset tracking, alert tone, improved QSO/logging flow.
- FT4: receive support through the weak-signal desk.
- JS8: receive/transmit working, including `@HB` heartbeat preservation and manual TX offset controls.
- WSPR: receive working. TX intentionally deferred.
- SSTV: receive/transmit working for common ham modes, with MMSSTV-derived RX work, FSKID support, TX templates, and image archive integration.
- WEFAX: receive working well, with a more useful desk, schedule view, and better long/live image stabilization.
- RTTY: fldigi-derived sidecar path in place, manual audio tuning/tune helper, usable decode roughly comparable to the IC-7300 on poor signals.
- FreeDV: RADEV1 native path is wired and testable, with separate decoded-speech audio lane, reporter integration, and harnesses. Live decode is usable but still needs more source-faithful cleanup and live capture validation.
- Voice desk: POTA spot submission, S-meter, PTT controls, and logging flow are usable.
- Longwave/logging: logbook selection, QRZ upload handling, and cross-mode logging flows are mostly in place.

Still rough or intentionally deprioritized:

- CW: currently still not satisfying. The old Python/adaptive paths were mostly cleared or deprioritized; the fldigi-style direction exists, but CW remains the dragon.
- PSK31/63: sidecar/desk scaffolding exists, but live signals have been scarce and this is not yet proven like FT8/JS8/SSTV/WEFAX.
- FreeDV callsign/report metadata: audio path is much improved, but callsign decode and end-of-transmission gibberish still need attention.
- WSPR TX: useful eventually, but not urgent because it is more propagation beacon than QSO workflow.
- Q65/MSK144: removed from near-term roadmap because they are mostly VHF/UHF or antenna/situation mismatched for this station.
- VARA/VarAC: useful but closed/proprietary enough that integration needs a careful plan later.

## Known Gotchas

- `docs/*` is ignored by default. Any new long-lived doc must be explicitly unignored in `.gitignore`.
- `publish/` is ignored. Installer binaries will not be pushed unless explicitly handled elsewhere.
- `src/ShackStack.Desktop/DecoderWorkers/` is ignored. Workers are expected to be rebuilt and packaged into the installer.
- `vendor/mmsstv/` is currently untracked. Do not assume it will survive a clone unless committed, submoduled, or archived manually.
- Avoid casual changes to WSJT-X/FT8 timing-sensitive code. That path was painful to stabilize and is currently performing well.
- SSTV auto-start can be too permissive or too selective depending on signal quality. Future tuning should use synthetic noise harnesses and MMSSTV comparison, not guesswork.
- FreeDV audio should keep raw radio RX audio and decoded speech on separate lanes. Do not reintroduce clever muting that breaks global audio.
- QRZ upload errors can be legitimate subscription/API responses. The app now surfaces sane rejection messages.
- Windows Time sync matters for FT8/FT4/JS8. The app has SNTP assistance, but Windows time should still be sane.

## Recommended Resume Order After Reinstall

1. Restore or clone the repo.
2. Restore ignored artifacts/source caches if they were archived.
3. Run `git status --short` and confirm whether the dirty handoff changes are present.
4. Install dependencies from the checklist.
5. Build the desktop app.
6. Build decoder workers.
7. Run SSTV regression and lifecycle probes.
8. Run FreeDV dry-run/receive-chain harness with known WAV samples.
9. Build the installer.
10. Launch the app and smoke-test desks in this order: Weak Signal, SSTV, WEFAX, FreeDV, RTTY, Voice/logging.
